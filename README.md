軟體流程改善研究-交友軟體

## 配對頁（`pages/match.html`）

純前端 demo（HTML + CSS + JS，不使用框架），沒有後端與資料庫；模擬資料以 JS 檔載入，**直接用瀏覽器開啟 `pages/match.html` 即可使用**，不需要架伺服器。

### 檔案結構

| 檔案 | 用途 |
|---|---|
| `pages/match.html` | 配對頁 |
| `pages/match.css` | 配對頁樣式（只使用 `theme_guide/theme.css` 的變數與 `dp-` 元件，頁面 class 加 `match-` 前綴） |
| `pages/match.js` | 畫面邏輯：卡片、評分、篩選、寵物管理、點數、開啟聊天 |
| `js/match-logic.js` | 不碰畫面的純邏輯（評分規則、篩選、驗證、點數、聊天門檻），可單獨測試 |
| `data/mock-data.js` | 模擬後端資料：14 位用戶（含登入帳密、每人 2 則問答）、12 隻寵物、32 筆預設評分 |
| `data/mock-chats.js` | 模擬聊天資料：9 段對話（u09 刻意沒有對話，用來示範空狀態） |
| `js/session.js` | 登入狀態（登入頁、配對頁、訊息頁共用） |
| `chat/chat-store.js` | 對話資料邏輯與儲存（配對頁開通聊天、訊息頁讀寫訊息共用） |
| `tests/*.test.js` | 邏輯測試（配對規則、登入狀態、對話資料） |

> 為了串接流程，也修改了登入頁（`pages/login.html`、`js/login.js`、`css/login.css`）與訊息頁（`pages/chat.html`、`chat/chat.js`），已事先與負責的組員溝通。

### 登入與測試帳號

- 從 `pages/login.html` 登入，帳號 `u01@nknu-demo.app`～`u14@nknu-demo.app`，密碼皆為 `demo1234`（登入頁上也有顯示）。
- 登入成功後前往配對頁；若是從其他頁被導回登入頁，登入後會回到原本那一頁。
- 沒有登入就打開配對頁或訊息頁，會導回登入頁。
- 勾「保持登入狀態」：關掉瀏覽器再打開仍是登入狀態；沒勾則關掉瀏覽器後需要重新登入。
- 個人中心的「登出」會清除登入狀態（沿用原本清除 `userToken` 的程式，未修改個人中心）。

每位用戶登入後都看得到有人給自己加分（卡片上的「給你 +N」）；除了 `u09` 之外每人都有對話。

### 功能與規則

**版面與導覽**
- 側邊欄（桌機、平板）與底部分頁列（手機）沿用聊天頁 `chat.html` 的導覽：探索、配對、訊息、我的檔案。

**配對模式**
- **一般**：所有用戶在同一個卡池，不限性別，可在篩選中指定。
- **寵物**：以自己的寵物身分和其他寵物配對。
- **長輩**：只有 65 歲以上用戶可使用（登入後預設進入），只顯示 65 歲以上的對象，介面字級與按鈕放大。

**評分（取代左右滑）**
- 關係分數滿分 100%，每按一次 +5 / -5，分數為 0 時只能加分。
- 分數上限：異性配對女方 60%、男方 40%；同性配對各 50%；寵物配對各 50%。
- 第一次加分可以留一句話給對方（只有這一次機會）。
- 雙方都加過分即配對成功。

**照片清晰度**
- 人的照片依關係分數（雙方加總）逐步變清楚：0% 時霧化但看得出輪廓，60% 以上完全清晰。
- 寵物照片不模糊。

**開啟聊天**
- 關係分數（雙方加總）達 60% 才能開啟聊天，與照片完全清晰同一個門檻。
- 達到門檻時跳出「可以和○○聊天了」，同時在聊天資料建立對話（模擬後端開通聊天），評分欄出現「和○○聊天」按鈕，連到 `chat.html?peer=<用戶 id>`。
- 寵物配對是和對方寵物的主人聊天。
- 配對成功（雙方都加過分）但未達 60% 時，會提示還差多少才能聊天。

**訊息頁（串接後）**
- 對話列表依登入者從聊天資料產生：還沒傳過訊息的放在上方「新配對」，其餘依最後訊息時間排序，顯示未讀數。
- `chat.html?peer=<用戶 id>` 直接開啟和該用戶的對話；還沒開通（分數未達 60%）時會提示，並開啟最近的對話。
- 對象的姓名、頭像、在線狀態、共同興趣都讀 `MOCK_DB.users`；傳出的訊息會保存，重新整理後仍在。
- 聊天建議、破冰話題（`chat/chat-ai.js`）沿用原本的程式，未修改。

**卡片**
- 預設收合，整頁剛好一個畫面高、不需捲動；點卡片空白處展開，顯示自我介紹、完整資料與動態。
- 支援多張照片，點照片左右兩側切換。

**篩選**
- 右上角篩選鈕開啟浮動面板，按「確定」才更新配對結果。
- 一般模式：性別、年齡、距離、學校、工作領域、興趣；長輩模式：性別、距離；寵物模式：種類、體型、個性。

**寵物管理**
- 寵物模式中可新增、編輯、刪除自己的寵物（品種、個性、外觀、介紹、最多 4 張照片）。
- 刪除寵物會一併刪除牠的評分紀錄。

**點數與動態**
- 每位對象（人或寵物）都有動態，花 30 點可永久解鎖。
- 點數取得：模擬課金方案（NT$30／100 點、NT$90／330 點、NT$150／600 點），或在點數面板手動輸入點數（任務系統之後由其他組員製作，目前以此模擬）。

### 資料儲存

資料都存在瀏覽器的 `localStorage`，只存在該瀏覽器中，換瀏覽器或電腦不會同步：

| key | 內容 |
|---|---|
| `nknu-match-demo-v5` | 評分、寵物異動、點數與解鎖紀錄 |
| `nknu-chat-demo-v2` | 對話與訊息（第一次使用時由 `data/mock-chats.js` 產生） |
| `userToken` | 登入狀態（未勾「保持登入」時另用 sessionStorage 的 `nknu-session-alive`） |

所有帳號共用同一份資料，就像共用一個後端：例如 `u01` 傳給林予晴的訊息，用 `u02` 登入後在訊息頁看得到。

> 模擬資料變動時會把 key 的版本號加一（例如 `v4` → `v5`），讓瀏覽器裡舊的測試資料不再被讀取，改用新的初始資料。

### 尚未完成／限制

- 模擬資料中其他用戶不會主動回應評分，只有資料檔中預設的評分。
- 模擬資料的照片為佔位圖；在 `photos[].src` 填入圖片網址即可顯示真實照片。
- 新增的寵物沒有動態（動態只來自模擬資料）。
- 照片模糊為前端效果，正式上線時應由後端依分數提供不同清晰度的照片。

## 編輯個人資料頁（`pages/profile-settings.html`）

純前端 demo，沒有後端與資料庫，**直接用瀏覽器開啟 `pages/profile-settings.html` 即可使用**。

### 檔案結構

| 檔案 | 用途 |
|---|---|
| `pages/profile-settings.html` | 編輯個人資料頁（大頭照、暱稱、性別、職業、年齡、關於我、興趣標籤） |
| `css/profile-settings.css` | 頁面樣式 |
| `js/profile-settings.js` | 標籤選取（最多 5 項）、照片縮圖預覽、儲存與載入個人資料 |
| `js/user-center.js` | 個人中心若讀到已儲存的個人資料，頭像與暱稱改用使用者自己的 |

### 資料儲存

- 存在瀏覽器 `localStorage`，key 為 `nknu-profile`，內容為 JSON：

  ```json
  {
    "nickname": "暱稱",
    "gender": "male | female | other",
    "occupation": "IT | FINANCE | DESIGN | EDUCATION | MEDICAL | STUDENT | OTHER",
    "age": "25",
    "bio": "自我介紹",
    "tags": ["美饌探索", "國際旅行"],
    "avatar": "data:image/jpeg;base64,...",
    "updatedAt": "2026-10-05T08:00:00.000Z"
  }
  ```

- 照片上傳後先縮到長邊 400px、轉成 JPEG（品質 0.8）的 data URL 再存，避免超過 localStorage 容量（約 5MB）。
- 再次進入編輯頁會自動帶回已儲存的資料；個人中心（`user-center.html`）會顯示已儲存的頭像與暱稱，未儲存過則維持原本的預設資料。

### 測試步驟

1. 開啟 `pages/profile-settings.html`，上傳照片、填寫必填欄位、選幾個興趣標籤，按「儲存檔案並繼續」。
2. 出現「個人資料已成功儲存！」並跳到個人中心，頭像與暱稱應換成剛剛填的。
3. 點「編輯個人資料與簡介」回到編輯頁，所有欄位與照片應自動帶回。
4. 按 F12 →「Application」→「Local Storage」可看到 `nknu-profile` 的內容；刪除該筆即回到初始狀態。

### 尚未完成／限制

- 資料只存在目前這個瀏覽器，換電腦或換瀏覽器就看不到。
- 只存一份個人資料（單一使用者），尚未與登入帳號或配對頁的 `MOCK_DB` 用戶串接。
- 頁面沒有帳號、密碼欄位，如需「註冊帳號」功能需另外規劃。
